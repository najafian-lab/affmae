# Training performance

The release uses the benchmarked exact grouped attention backward, shared
neighborhood metadata, contiguous K/V packing, compact positional tables for
512/1024px models, cached canvas geometry, and decoder KNN reuse across stages.
Triton is the default KNN backend for supported CUDA/ROCm shapes. The rounded
FP16 tensor-core reduction and slower experimental tiled KNN are not enabled.

Single-GPU NVIDIA training captures forward, native loss, and backward by default.
Optimizer steps, gradient clipping, GradScaler updates, and input loading remain
eager. The trainer preserves gradient accumulation, RNG, mutable buffers, and
changing loss scales. Batch-shape changes run eagerly, as do CPU, AMD, and DDP.
Capture OOM falls back to eager training. See [training controls](train.md).

PyTorch 2.10.0+cu128, Triton 3.6.0, and timm 1.0.29. Measurements use this

FP16 and CUDA graph replay;
ViT is forced to use FlashAttention. Each row uses batch 4, five alternating
measurement rounds, ten warmup passes, and twenty timed passes per round.

| pretrain | 512 | 53.51 | 28.26 | 1.90× | 4.10 | 2.18 | 1.88× |

Timings include the complete forward, native loss, and backward. They exclude
loading/resizing, compilation/capture time, gradient clearing, optimizer steps,
and scaler updates. They are not epoch timings or complete optimizer-step times.
Memory is peak allocated GPU memory, including warmup/capture and backward
caches, but excluding optimizer/scaler state. Speedup and memory factors are
ViT divided by AFF; larger means faster/lower memory for AFF.

All performance measurements use real `fpwdata` microscopy images and paired
segmentation labels, cached before timing. The 512px cases resize the same real
1024px inputs; images use antialiased bilinear interpolation and labels use
nearest-neighbor interpolation. Synthetic tensors are used only for targeted
correctness tests, not speed measurements.

Both use 8px patches and approximately 65M trainable parameters. Pretraining uses
50% masking. Finetuning compares the native AFF deformable decoder with ViT's
UperNet decoder. AFF uses the released pretraining checkpoint; ViT uses seeded
initialization. These measurements establish speed and memory, not equal mIoU.

## Reproduce locally

Install a PyTorch build compatible with your GPU, then install the repository
extras and run the benchmark from the repository root:

```bash
pip install -e ".[cuda,baselines,inference,train]"
python scripts/benchmark.py --data-root /path/to/fpwdata
```

The data directory should contain `train/images/*.tiff` and matching filenames
under `train/masks/`. The script loads the first four sorted real images and
paired labels once, using the repository preprocessing. It downloads the released
AFF pretraining weights on first use; pass `--checkpoint /path/to/weights.pth`
to use a local copy. ViT uses seeded initialization. No synthetic images are
generated.

Defaults reproduce the table: both tasks, 512/1024px, batch 4, FP16, five rounds,
ten warmup passes, and twenty timed passes. Each model runs in a fresh process,
with model order alternating between rounds. CUDA graphs are enabled on NVIDIA;
`--eager` disables them for both models and is automatic on ROCm. FlashAttention
must be available; the script fails rather than silently using math attention.

For a shorter check or a GPU with less memory:

```bash
python scripts/benchmark.py --data-root /path/to/fpwdata \
  --task pretrain --resolution 512 --batch-size 1 --rounds 1 \
  --output output/benchmark-small
```

Use the same batch size for both models. Finetuning requires batch size 2 or
larger because ViT's UperNet head uses BatchNorm after global pooling.
Results at a different batch size, backend, or GPU are separate comparisons.
The default 1024px finetuning case
requires roughly 26 GiB of allocated memory for ViT, plus CUDA runtime overhead.

`output/benchmark/` contains per-round JSON and logs, `run.json` with input paths
and arguments, `summary.json`, and `TABLE.md`. Choose a new `--output` directory
for each run. Times are medians across rounds; speedup is the median of paired
ViT/AFF ratios, and memory reduction divides the models' median peak allocations.
An optional `--inputs real_batch.pt` accepts an already preprocessed real-data
cache containing `images` shaped `[B,1,1024,1024]` and integer `targets` shaped
`[B,1024,1024]` with labels 0–2. Labels are optional for pretraining alone.

## Numerical checks

The compact grouped reducer preserves the generic reducer's FP32 accumulation
order. Isolated backward comparisons cover masked tail clusters and head widths
32/48/64. Graph integration tests cover gradient accumulation, scale changes,
overflow recovery, mutable buffers, RNG, changing batch shapes, and eager fallback.
Local validation passed 228 inference/kernel/integration tests (four optional
tests skipped), plus 139 cache/device/import/engine checks. Six graph/table tests
also passed on the RTX 5090.

Full-model training has nondeterministic reductions in eager mode. On GH200,
the largest parameter differences after two accumulated AdamW updates were
0.000306 (graph/eager) versus 0.000303 (eager repeat) for pretraining, and
0.000120 for both comparisons in finetuning. These are repeat-noise controls,
not a claim of bit-identical full-model training trajectories.

On RTX 5090, the same real-image training-engine checks completed two accumulated
AdamW updates with changing loss scales and finite parameters. Maximum parameter
differences were 0.000307 (graph/eager) versus 0.000302 (eager repeat) for
pretraining, and 0.000119 versus 0.000120 for finetuning.

The RTX 5090 compact-reducer comparisons were bit-identical for all three tested
tail/head-width cases, and Compute Sanitizer reported zero errors. Autotuning
was cached before instrumentation to avoid sanitizer-induced tuning OOM; the
performance runs used the normal defaults.

## Public inference

`AFFMAE.from_checkpoint()` and `AFFMAE.from_model()` enable FP16 autocast and
CUDA graph replay by default for NVIDIA segmentation inference. This applies to
`forward()`, `segment()`, `segment_batch()`, the CLI, and the demo. First use
warms up and captures the model; subsequent calls replay it with new image data.
Preprocessing, CPU transfers, and rendering remain outside the graph.

The cache holds at most two shape/layout/precision combinations per predictor.
Additional combinations and failed captures run eagerly. CPU, ROCm, parallel
wrappers, training, and masked reconstruction use eager execution. Returned
logits, token locations, and features remain valid after subsequent predictions.

```python
# Keep graph replay but retain FP32 precision.
model = AFFMAE.from_checkpoint("AFFMAE_BASE_FT_512", amp=False)

# Disable graph replay as well.
model = AFFMAE.from_checkpoint("AFFMAE_BASE_FT_512", amp=False, cuda_graph=False)
```

An outer autocast context takes precedence over `amp`. Call
`model.clear_inference_cache()` after replacing model parameters or changing
model configuration. This also releases the captured graph pools.

FP16 is a precision choice, separate from graph replay. On all 235 FPW test
images at 512px with the released 512px finetuned checkpoint (GH200), foreground
mIoU was 56.906% in FP32 and 56.877% in FP16; pixel agreement was 99.925%.
Maximum logit difference was 30.67, so FP16 is not numerically identical to FP32.
At fixed FP16 precision, graph and eager logits were bit-identical on all 235
images. Separate checks preserve labels and encoder stage metadata exactly on
the tested real images at both 512px and 1024px.

The public `AFFMAE.forward()` path was measured on RTX 5090, batch 4, with real
images, five fresh-process rounds, ten warmups, and thirty timed calls per mode.
These timings include graph input/output copies, but exclude preprocessing,
CPU transfers, and capture. Initialization matches the training comparison above.

| Resolution | FP32 + graphs ms | FP16 + graphs ms | FP16 gain | Gain vs FP32 eager |
|---|---:|---:|---:|---:|
| 512 | 25.17 | 14.50 | 1.74× | 2.57× |
| 1024 | 91.07 | 52.11 | 1.75× | 1.75× |

The precision gain compares FP16 and FP32 with graphs enabled for both. FP16
alone was slower at 512px in eager mode (47.41 vs 37.28 ms), which is why the
public NVIDIA default enables graph replay together with FP16.
